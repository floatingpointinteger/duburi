# IVC Decoder

The `decoder.py` is a script that I wrote for the RoboSub competition's inter vehicle communication section (IVC) for **`Duburi`**. It is an underwater wireless communication system built for the competition. The script takes sound, analyzes frequency, locks onto correct frequency band and decodes a UART-like signal.

`decoder_debugger.py` was generated with AI assistance.

## Hardware

The hardware consisted of a car horn and IP66 mic.

### Car Horn

Car horn model: Desco disc horn

https://aftermarket.denso.com.sg/product_info/?cat_id=182

### Microphone

Mic: Generic IP66 mic

https://www.alibaba.com/product-detail/High-Sensitivity-Waterproof-Audio-Pickup-Microphone_1601491272127.html?.com

### Sender

An N-type MOSFET was used to produce the signal using the horn. A protective enclosure waterproofs the horn.

### Receiver

The IP66 mic receives the signal. A Windows computer runs `decoder.py`.

## Protocol

The car horn as a transducer has imprecise timing, so a simplistic UART-like solution was used.

The horn frequency cannot be changed and amplitude falls off by distance.

The signal is generated by turning the horn on/off and measuring how long the horn stays on.

Start/end bits are used to remove corrupted packets.

Separate time durations encode 1s and 0s.

No max byte (1/0) length was introduced to keep code modular; this did not cause problems for the start/end structure.

Max length could significantly lessen the possibility of corrupted signal detection.

## Decoder

The team preferred Python, so Python was used for the decoder.

`sounddevice` library was used to create a separate thread for audio input collection and run decoder logic concurrently.

Queue stores audio input.

Frequency tolerance accounts for horn imprecision.

Energy in a large frequency band was used to detect signal.

Error was used because horn timing is imprecise.

Adaptive energy thresholding / Alpha was used because decoder couldn't reliably detect fluctuating sound amplitude.

Alpha was found via testing: a dry run with controlled amplitude was performed. For each test I checked how amplitude threshold scaled for optimal result. Points were plotted and a linear line was drawn. Alpha is the tangent/slope of the line.

Time is measured using time steps `SIZE / FS` rather than local system time to avoid synchronization problems.

FS and size seemed not to have significant effect on decoding, so standard values were used.
